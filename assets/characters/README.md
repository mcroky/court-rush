# COURT RUSH / 사람형 캐릭터 v1

현재 런타임은 **v2 / v0.6.25**다. 아래 v1 기록은 첫 제작의 배경이며 최신 값은 다음을 따른다.

- 얼굴 크기/턱/광대/눈두덩/코, 목·쇄골·삼각근·팔꿈치 형상을 다시 만들었다. 얼굴은 내장 imagegen으로 생성·편집한 [일러스트 텍스처](face-painted-v2.png)와 [전체 프롬프트](face-painted-v2.prompt.txt)를 사용한다. 실제 결과의 눈/코/입 위치에 UV를 맞추며 피부색에 맞춰 가장자리를 섞는다. 포트레이트 평면을 머리 앞에 붙이지 않는다.
- 저지 허리/겨드랑이와 반바지에 실제 변위 주름을 만들고 법선을 재계산했다. 번호를 별도 부유 표면에서 옷 UV2의 프린트로 옮겼다. 반바지는 D자형 반쪽 허리에서 양쪽 다리로 이어지는 표면으로 연결한다.
- 청록07 **12,998삼각형**, 주황23 **13,094삼각형**, 각각7개 표면. 얼굴 표면을 추가하는 대신 프린트 표면을 통합해 표면 수를 유지했다. 원단 변형과 성인 얼굴 윤곽을 위해 v1 대비 형상 예산을 늘렸고, 현재 상한은14,000삼각형/선수다. 본45개·최대4가중치는 유지. 새 텍스처는 임포트 시 최대1024px 및 mipmap을 사용한다.
- 리그의 접점 보정은 이동 컨트롤러의 속도를 다시 제한하지 않는다. 실제 접지를 보존하고 짧은 스윙/착지 전환을 완료한다. 프로젝트 `docs/06-motion-rebuild.md`와 검증 기록을 참조한다. 모바일 실기기 성능/LOD는 후속 측정이다.

실제 경기 양쪽 선수의 화면용 메시. 원작 게임의 모델·텍스처를 사용하지 않은 자체 제작 형상이다. 방향은 긴 팔다리의 운동선수, 작은 눈매와 각진 코, 짧은 검은 머리, 청록/테라코타색의 스트리트 농구복이다. 원본 게임 재현 완료나 최종 작화 승인을 뜻하지 않는다.

- 엔진: Godot 4.7.2 Standard / Compatibility. 기존 `RiggedStreetVisual`의 45본 리그와 idle/run 및 손바닥·앞꿈치 접촉을 유지한다.
- `rush_player.res`: 청록 07번, 7,722삼각형. `rush_rival.res`: 주황 23번/헤드밴드, 7,786삼각형. 각각 7개 재질 표면, 4개 이하 가중치/정점. 두 자산은 압축 네이티브 ArrayMesh이며 인스턴스 간 공유한다.
- 사람 피부·의상·얼굴·머리카락 모두 하나의 스킨 메시 안에 있다. 몸통/팔꿈치/무릎은 혼합 가중치를 쓴다. 손가락은 원본 뼈를 따르고 새끼손가락만 약지 리그를 공유한다. 새 손 뼈나 접촉점은 추가하지 않았다.
- 봉제된 목둘레/암홀, 옆면 패널, 원단 미세 격자/통기공, 작은 주름, 밑단, 손목밴드, 양말과 고무 밑창을 제작했다. 원단 패턴은 화면 미분으로 먼 거리에서 약화해 반짝임을 줄인다. 번호/브랜드는 자체 SVG 도형이며 외부 글꼴을 포함하지 않는다.
- 원본 마네킹 메시만 숨긴다. 원본 GLB·Skin의 named inverse bind·Skeleton3D·AnimationPlayer 및 게임 판정은 그대로 쓴다. 새 외형을 기존 구형 절차적 부품으로 되돌리지 않는다.
- 출처/라이선스: `provenance.json`, 프로젝트 `THIRD_PARTY.md`, 원본 리그의 `assets/experiments/mannequiny/LICENSE.txt`. 자체 메시를 사용해도 원본 리그/클립의 CC BY 4.0 고지는 유지한다.

재제작 순서:

1. 번들 Python으로 `tools/build_jersey_marks.py` 실행.
2. Godot `--headless --path . --editor --import`로 SVG 가져오기.
3. Godot `--headless --path . --script tools/build_player_mesh.gd`로 리그의 실제 inverse bind 좌표에서 메시 작성/저장. 스켈레톤의 현재 포즈를 T포즈라고 가정하지 않는다.
4. `tests/human_visual_test.gd`, `rig_gameplay_test.gd`, `rig_transition_test.gd` 실행 후 웹 캐릭터 스튜디오/실제 코트에서 확인.

모바일 기준은 현재 단계의 형상 예산이다. 실기기 GPU 시간·장시간 발열/메모리 검증과 최종 LOD 제작은 후속 작업이다. 스킨/의상 교차를 수치 검증만으로 최종 승인하지 않는다.
