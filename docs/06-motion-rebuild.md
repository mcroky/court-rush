# 모션 제작 방식 전환 — 2026-10-24

## 2026-10-25 로컬 미리보기: 수비 접지와 공 없는 팔 연결

수비의 물리 옆걸음과 실제 스킨 발이 서로 다른 시계로 움직여, 발을 딛었다는 판정 뒤에도 화면에서는 별도의 회수 스윙이 시작됐다. 수비 중에는 Actor의 한 번의 교대 스윙 진행도를 공유하고, 표시 발의 현재 위치에서 같은 착지 목표까지 연결한다. 발을 옮기는 시간은120~160ms이며 방향 반전 직후에도 방금 디딘 발을 다시 선택하지 않는다. 달리기 입력 응답이나 공격 돌파 회복 규칙은 유지한다.

`movement_step`과 `settle_guard_support`의 지지 다리 길이에도 `height_ratio`를 적용한다. 메시와 숨겨진 접촉용 몸체를 신장에 따라 조절하면서 두 계산만 기본 길이를 사용해,178cm 가드에게 실제보다 긴 지지 거리를 허용하던 누락을 수정했다. 더 깊이 웅크리거나 발 교대를 급하게 만들어 우회하지 않는다.

달리기에서 낮은 수비로 들어갈 때 회수 중인 발이 골반에서 너무 멀거나 떠 있으면 먼저 그 스텝을 마친다. 이후 수비 지지 발을 잡아 몸 전체의 급강하를 막는다. 수비 가중치가 바뀌는 구간에도 발바닥 높이 보정을 유지하고, 지지 다리의 길이 안에서 골반을 낮춘다. 수비 중 일반 질주 클립의 몸통 반동을 섞지 않고 앞쪽 상체 기울기·교대 디딤의 체중 이동·등 접촉 압박을 적용한다.

공 없는 달리기 팔과 수비 팔은 연속 가중치로 연결한다. 팔꿈치 굽힘 방향은 어깨와 함께 이동하는 안정된 기준을 사용하고, 수비 손은 어깨보다 아래에서 펼친다. 박스아웃에서는 손을 옆/뒤로 낮추며, 수비 해제 때 팔뚝과 손목이 달리기 자세로 돌아간다. 블록·스틸·리바운드의 실제 접촉 스윙에는 일반 수비 손목 속도 제한을 적용하지 않는다.

`character-lab.html`의 낮은 수비·좌우 수비·박스아웃은 실제 Actor를 구동한다. 정면·측면·느린 재생으로 자세 진입, 방향 반전, 멈춤, 회복을 비교할 수 있다. 별도의 전용 농구 모션캡처 자산 도입은 아니며, 정량 회귀 결과와 시각적 자연스러움은 구분한다.

사용자 피드백: 반복된 관절·타이밍 보정이 눈에 띄는 전신 동작 개선으로 이어지지 않는다. 자연스러움에 대한 이 피드백을 수치 검사 통과로 반박하지 않는다.

## 현재의 한계

`actor.gd`는 부품 메시를 관절 목표에 맞춰 배치하고, 동작별 분기에서 몸통·팔·다리를 계산한다. 접점/길이/타이밍 검사는 오류 방지에는 유효하지만 제작된 전신 포즈, 무게 이동, 의상 변형과 실루엣을 대신하지 못한다. 작은 보정을 추가하는 방식을 주된 모션 제작 경로로 계속 확대하지 않는다.

## 이번에 만든 비교 시제품

- GDQuest/기여자·Luciano Muñoz의 Mannequiny를 원본 GLB 그대로 가져왔다. 고정 커밋과 SHA256/CC BY 4.0/출처 기록은 `assets/experiments/mannequiny/provenance.json`, 고지는 `THIRD_PARTY.md`와 비교 페이지에 둔다. 원본 Godot 3 컨트롤러는 사용하지 않고 Godot 4.7.2의 AnimationPlayer로 클립을 재생한다.
- 비교 모델은 최종 캐릭터가 아니다. 얼굴·의상 작화 목표를 바꾸거나 완성된 농구 모션으로 발표하지 않는다. 원본 달리기는 일반 달리기이며 농구 수비·크로스오버·드리블 클립이 아니다.
- 두 화면은 제자리 재생 비교다. 실제 경기의 루트 이동/접촉·공 제어와 새 클립을 통합한 것으로 보지 않는다. 왼쪽은 기존 접지 스케줄러, 오른쪽은 원본 키프레임이므로 발 위상과 보폭을 동일하게 맞춘 대조 실험도 아니다.

## 경기 적용을 위한 다음 제작 단위

1. 하나의 사람형 스킨 메시와 공통 리그를 최종 작화 방향에 맞춘다. 어깨·골반·팔꿈치·무릎의 변형과 옷 실루엣을 실제 코트 크기에서 먼저 검토한다. 현재 얼굴 텍스처만 새 몸에 붙여 품질 향상으로 간주하지 않는다.
2. 공 없는 낮은 달리기, 좌우 수비, 제동, 좌우 헛디딤, 지지 발 전환, 돌아서 추격의 짧은 전신 클립을 제작/선정한다. 시작/종료 속도와 발 접촉 위상을 기록한다. 농구 전용 클립이 없는 상태에서 일반 달리기 하나로 모든 동작을 대체하지 않는다.
3. AnimationTree의 이동 블렌드와 전환 조건을 만들고 실제 경기 속도에 맞춰 루트 이동/보폭을 연결한다. 타이머만으로 재가속하지 않고 접지 발, 무게 이동, 전환 포즈를 함께 사용한다. IK는 접점의 작은 보정에 한정하고 전신 포즈를 대신 생성하지 않는다.
4. 공은 손 뼈의 밀기/놓기/받기 사건과 연결한다. 한 손 드리블, 양손 확보, 슛 릴리즈, 리바운드 캐치, 블록 타격을 구분하며 손에 닿지 않는 공을 임의로 끌어오지 않는다. 기존 규칙·공 접촉 검사를 통합 시 보호한다.
5. 일반 달리기/수비 회복 한 묶음을 실제 조작으로 검토한 뒤 나머지 농구 동작으로 확장한다. 모델을 바꿨다는 사실이나 뼈 수가 많다는 이유로 품질을 승인하지 않는다.

## 완료 기준

- 실제 조작 중 정지/방향 전환/추격에서 발과 공이 미끄러지거나 순간 이동하지 않는다.
- 어깨·팔·골반의 위상이 전신 클립 안에서 연결되고 전환 프레임에 포즈가 튀지 않는다.
- 1대1에서 돌파 성공으로 만든 공간과 합법적인 회복·추격 수비가 모두 살아 있다.
- 같은 코트 시점의 전후 연속 캡처와 사용자의 실제 플레이 관찰로 판단한다. 수치 테스트와 체감 평가는 구분한다.
- 모바일 목표를 위해 모델/텍스처/뼈 수·애니메이션 압축·프레임 비용을 측정한 뒤 주 캐릭터 전환을 결정한다. 이번 실험은 모바일 실기기 성능 검증이 아니다.

## v0.6.23 적용 상태

사용자의 실제 경기 적용 요청에 따라 양쪽 경기 캐릭터를 스킨 리그로 기본 전환했다. `rigged_visual.gd`가 원본 전신 idle/run, 클립 전환, 접점/드리블 팔 보정과 경기용 손바닥 위치를 담당한다. 기존 부품 모델은 숨겨진 기술 목표/접지 상태 계산용으로 남겼다. 실제 코트에서 새 리그를 기본으로 사용하며 별도 비교용 토글에만 한정하지 않는다.

달리기/드리블/일반 컷/헛디딤→추격의 첫 통합을 완료했다. 슛과 수비 기술도 같은 메시에서 기존 목표를 따르지만, 전용 농구 전신 클립 제작과 최종 얼굴·의상/모바일 성능 측정은 남았다. 위 제작 단위2~4가 모두 완료된 것으로 보지 않는다. 정량 결과와 관찰 한계는 `04-prototype-validation.md`의 v0.6.23 기록을 따른다.

## v0.6.24 사람형 외형 적용

마네킹의 화면용 메시를 새 사람형 피부·얼굴·머리카락·농구복으로 교체했다. 편집 가능한 형상 제작 소스는 `tools/build_player_mesh.gd`, 실제 경기 자산은 `assets/characters/rush_player.res`와 `rush_rival.res`다. 새로운 뼈대를 만들거나 접촉 목표·클립 시간을 바꾸지 않고 원본 named inverse bind로 스키닝한다. 기본 전신 리그·드리블 팔 계층·컷/추격 연결·손바닥/앞꿈치 판정은 이전과 동일하다.

목/등/몸통·팔꿈치·무릎에는 혼합 가중치를 사용하고, 반바지는 골반의 허리 부분과 허벅지를 따르는 넓은 바짓단으로 구성한다. 초기의 큰 골반/허벅지 혼합은 회전 중 천이 다리 안으로 말려드는 문제가 있어 바짓단 가중치를 허벅지로 정리했다. 어깨는 독립된 구형 관절처럼 보이지 않게 쇄골에서 델토이드·위팔을 잇는 연속 표면으로 작성했다. 얼굴의 코/턱/눈매와 농구복의 표면/번호는 모두 새 형상/자체 그래픽이다.

`/character-lab.html`은 실제 경기와 같은 StreetPlayer를 불러오는 외형 확인 장면이다. 기존 `/motion-lab.html`의 원본 마네킹 비교는 역사적 대조용으로 유지한다. 두 장면의 목적을 구분하며, 사람형 외형 적용이 모든 농구 기술의 새 전신 클립 제작이나 최종 작화 승인, 모바일 성능 측정 완료를 뜻하지 않는다.

## v0.6.25 구조 수정과 캐릭터 v2

새 리그 자체를 폐기하지 않고 잘못 연결된 계층을 분리했다. 거의 일직선인 원본 무릎 점으로 굽힘 평면을 추정하던 방법은 발 목표가 바뀔 때 역관절을 만들었다. 전방/바깥의 해부학적 평면을 사용하고, 새로 획득한 실제 접점을 구형 신발 목표로 덮어쓰지 않는다. 렌더 리그는 이동 컨트롤러의 이동량을 다시 제한하지 않는다. 원래 이동/접지 컨트롤러가 루트를 소유하며 렌더 리그는 예측 착지점까지 하나의 스윙을 완료한다. 도달 한계에서는 발을 끌거나 루트를 정지시키는 대신 앞꿈치를 떼고 다음 스윙으로 전환한다.

스윙은 컷 상태가 끝나도 마무리하며 100ms의 다리 포즈 복귀를 둔다. idle/run 전환 역시 직전 실제 포즈에서 이어진다. 한 접지 구간에서 도달 한계로 해제된 발을 매 프레임 다시 잡지 않는다. 기본 루트 높이와 접지에 필요한 골반 보정을 분리해 보정값을 다음 프레임에 중복 누적하지 않는다. 초기화/뷰 회전 때 이전 월드 발 위치를 새 포즈의 출발점으로 사용하지 않는다.

자유 팔은 원본 전신 클립으로 안전하게 복귀하고, 스틸은 낮은 실제 공으로 상체를 숙이고 어깨/손가락을 뻗는다. 이전의 허리 높이 손 목표와 위쪽을 보는 손가락 프레임 때문에 짧은 새 팔이 실제 공에 닿지 않던 문제도 수정했다. 뼈 길이, 접촉 거리/시간, 스틸 확률은 늘리지 않았다.

캐릭터 v2는 작은 성인 머리/턱/광대/눈두덩/코와 승모근-쇄골-삼각근 연결, 실제 팔꿈치/무릎 축에 맞춘 표면, 연결된 반바지 허리/가랑이, 허리/겨드랑이 입체 주름을 사용한다. 얼굴 일러스트 텍스처와 원단 UV2 프린트/미세 패턴은 같은 스킨에 묶인다. 기존45본과 원본 GLB/클립은 보존한다. 약1.3만 삼각형/7개 표면과 최대1024px 얼굴 텍스처는 로컬 시제품 예산이며 모바일 실기기/LOD 측정을 대체하지 않는다.

## v0.6.26 이동 반응과 농구 자세의 분리

기존25도 방향 변경은 완전 감속→정지→세 걸음 재가속을 강제했다. 일반적인 방향 입력은42m/s²의 짧은 방향 가속과 지지 발 교환을 사용하고, 루트 회전은 초당7rad로 제한해 팔·어깨가 순간 회전하지 않게 한다. 입력을 놓은 정지와 헛디딘 수비의 회복은 별도 상태로 유지한다. 보통 스킨 달리기는 숨긴 구형 다리의 도달 한계로 이동을 중단하지 않는다. 실제 표시 발의 고정/도약과 경기 충돌은 유지한다.

골반을 깊게 내리기만 한 중간 시제품은 무릎이 지면 가까이 접혀 서기/달리기로 부적절했다. 최종은 공 보유 기본 루트 오프셋-5.5cm, 달릴 때 추가-4.5cm로 제한하고, 전방 척추 기울기·짧은 발 회수·지지 발 뒤꿈치 들기를 함께 사용한다. 원본 발 궤적은 보폭72%, 높이48%의 농구 이동으로 바꾸고, 실제 발에서 다음 목표까지 연속 이동한다. 낮춘 골반에 원본의 높은 발 들기를 그대로 더하지 않는다. 접지 보정까지 적용한 최종 골반 높이를 완만하게 이어 급정지 후 솟는 것을 막는다.

자유 팔은 보이는 양다리의 앞뒤 차로 반대 박자를 계산한다. 손가락 방향은 실제 팔뚝과 이어지고 손바닥은 안쪽으로 향한다. 드리블 팔은 구형 팔의 제한된 목표 대신 실제 공 경로를 새 리그에 재타기팅하고, 짧은 쇄골 보조 회전과 안정된 팔꿈치 굽힘 평면을 쓴다. 공 정점1.10→1.06m와14cm 손 간격으로 팔을 완전히 펴는 특이점을 피한다. 공의 높이는 몸통 흔들림과 분리하고, 실제 반지름12.5cm를 바닥 반발/손 접촉의 공통 기준으로 사용한다.

두 손 보유 대기에서는 실제 양 손바닥을 공의 양옆에 두고 팔꿈치를 굽힌다. 일반 슛은 슈팅 손이 공 아래에, 보조 손은 공 옆에 자리 잡는다. 준비 포켓에서 상승하며 팔꿈치를 공 아래에 유지하고, 보조 손이 떨어진 뒤 릴리즈 후 손목을 접는다. 기존 슛 입력/릴리즈 시점/득점/반칙 규칙과 원본 리그는 유지한다. 새 전신 농구 클립 제작 완료를 뜻하지 않으며 접촉 계층과 원본 클립을 조합한 현재 방식이다.

## v0.6.27 드리블 팔의 연속된 반복

공 높이·반복 속도와 이동/방향 전환은 유지하고, 실제 스킨 팔의 경로를 수정했다. 기존에는 누르기가 끝나자마자 손을 최고 높이로 회수하고 고정된 손바닥 방향으로 기다렸다. 어깨 바깥/뒤쪽 굽힘 평면과 결합해 팔꿈치가 들리고 공과 팔이 따로 움직였다.

같은 바운드 위상에서 손이 공을 누르는 구간을 유지하고, 놓은 직후에도 하향 속도를 이어 짧게 따라 내려간다. 이어서 팔꿈치를 접으며 공의 상승에 맞춰 회수하고, 최고점에서 받아 다시 누른다. 방출/회수/수신 경계의 손 높이와 속도를 연결한다. 손목은 누르기와 따라 내리기에서 살짝 접고 수신 전에 다시 펴며, 공 아래로 손바닥을 뒤집지 않는다. 실제 팔꿈치의 굽힘 목표는 갈비뼈 옆 아래로 옮긴다.

반대 팔의 발 박자, 원본 전신 클립과 45본 리그, 크로스오버의 실제 수신 판정, 두 손 확보 후 재드리블 금지는 유지한다. 제자리/달리는 드리블 모두 같은 반복을 사용한다. 수치 검사는 접촉과 연속성의 회귀 확인이며 자연스러움의 사용자 승인을 대신하지 않는다.
## v0.6.28 실제 손 기준으로 잇는 행동 전환

크로스오버 시작/종료와 수비 점프/리바운드 캐치의 스냅샷을 실제 스킨 손바닥에서 취한다. 화면 리그는 크로스오버 손 목표를 구형 팔의 도달 범위로 한 번 더 제한하지 않고 직접 받으며, 보내는 손의 회수는 원본 전력질주 팔이 아니라 실제 발 교대에 맞춘 농구 달리기 반대 팔 궤적을 따른다. 수신과 누르기의 접촉은 기존 공 위상을 유지한다. 손목 회전 제한을 자유 팔 정렬 뒤에도 적용해 보내는 팔이 자유 팔로 바뀌는 순간 방향이 튀지 않게 한다.

슛 준비/릴리즈와 레이업은 직전 실제 손 위치와 방향에서100ms에 걸쳐 시작한다. 레이업은 양손으로 낮은 포켓에 모으기, 보조 손 분리, 슈팅 손을 얼굴 위로 올리기, 릴리즈 뒤 손목 굽힘과 팔 회수를 나눈다. 기존 한 발 도약/진입 속도/릴리즈 시점은 유지하고 상체에 작은 비틀림을 더한다. 공은 실제 슈팅 손을 따라간다.

리바운드는 양손을 공의 양옆13.5cm로 뻗고, 캐치 시 실제 접촉 위치/공 속도를 잠깐 받아낸 뒤 머리 위 확보와 가슴 높이 보호로 연결한다. 확보 뒤에는 양손을12.5cm로 좁히고 손바닥을 공 안쪽으로 향하게 하며 손가락을 굽힌다. 기존 도약/착지/박스아웃·공중 캐치 판정과 역할 밸런스는 유지한다.

착지 시 구형 접지 배열이 비었다는 이유만으로 화면 리그까지 순간이동 초기화를 하던 연결을 분리했다. 실제 월드 이동이1.5m를 넘거나 명시적으로 자세를 리셋한 경우의 초기화는 보존한다. 발 접지를 재구축해도 화면의 손목·어깨·클립 복귀 이력은 이어진다.
## v0.6.29 크로스오버 수신과 첫 돌파의 전신 연결

기존 CrossClip의 몸통 신호는 숨겨진 구형 body/upper에만 들어가고, 화면 리그의 크로스오버는 ordinary locomotion으로 분류돼 그 신호를 사용하지 않았다. 실제 리그에도 같은 바운드 위상의 낮추기·어깨 비틀기·중심 이동을 적용한다. 공이 바닥에 닿는50%와 반대 손이 받는85%를 기준으로 재정렬하고, 실제 수신 후 첫280ms의 돌파까지 끝 자세를 이어서 달리기로 감쇠한다. 공 궤적/접촉/입력 가속이나 소유권 전환 시점은 변경하지 않는다.

원본 스프린트 클립은 별도의 큰 상체 회전이 있어 크로스오버의 회전과 단순히 더하면 어깨가 반대 박자로 흔들렸다. 화면의 실제 양 어깨선에서 현재 회전을 읽어 수신 방향으로 교정한다. 원본 회전을 상쇄하는 값은 해당 프레임의 원본 자세를 기준으로 적용하고, 몸통 신호와 진입/복귀 가중치는 연속적으로 유지한다.

원본 spine_02의 바인드 축이 대각선 앞쪽을 향하므로 이를 팔의 아래/앞 방향으로 사용하지 않는다. 실제 어깨선의 수평 방향과 중력을 기준으로 팔을 움직인다. 자유 팔의 손목과 손바닥 끝점을 번갈아 풀던 반복 방식 대신 손바닥을 연장된 팔뚝의 끝점으로 계산하고 실제 뼈 길이로 손목을 푼다. 낮은 팔꿈치 평면과 안정된 뒤쪽 굽힘 방향을 사용하며, 받는 손은 공 접촉 프레임을 유지한다. 첫 돌파의 자유 팔 목표는 실제 수신 직전 손 위치에서 이어진다.

스튜디오의 크로스오버는 실제 facing/steer/animate를 사용해 수신 뒤 방향 전환과 재돌파를 보여준다. 카메라 표현을 위한 시점 변경에서만 접지를 초기화하며, 반복 동작 중 루트 방향을 강제로 덮어쓰지 않는다.
### 공통 시선 보정

사용자의 전체 동작 피드백에 따라 팔/어깨 외에도 고개가 상태를 따라가지 않는 부분을 연결했다. 머리의 원본 rest forward를 기준으로 실제 현재 방향을 측정하고, 이동할 방향을 먼저 보거나 슛/공중 경합의 공을 올려다보도록 목표를 둔다. 확보 뒤에는 위로 고정된 시선을 풀고 가슴의 공 쪽으로 돌아온다. 목30%/머리70%의 작은 회전과 제한된 목표 변화 속도를 사용하며, 바운드·슛·블록/리바운드 판정이나 캐릭터 이동에는 개입하지 않는다. 전체 전용 농구 키프레임이 완성됐다는 뜻은 아니다.
## v0.6.30 달리기에서 슛·레이업 착지까지

점프슛 준비에서 접근 속도를 바로0으로 만들던 처리를180ms 감속으로 바꾸고 마지막 스텝을 마치게 한다. 공을 잡은 뒤에는 드리블을 다시 시작하지 않으며 최대 두 스텝 제한을 공유한다. 기존 짧은 D 페이크와 골밑 러닝 피니시 자동 확정은 유지한다. 슛 준비의 감속은 입력 응답을 늦추는 전역 필터가 아니다.

점프슛은90ms의 지상 밀기 뒤720ms까지 포물선으로 뜨고, 레이업은 기존120ms 한 발 밀기와820ms 체공 시간을 쓴다. 릴리즈 시점은 슛220ms/레이업340ms를 유지한다. 실제 화면 리그가 직전 골반 높이와 발끝을 저장하고, 밀기 구간은 고정 발끝 위에서 뒤꿈치를 들며 골반을 편다. 지상→체공의 높이와 상승 속도를 Hermite 곡선으로 잇는다. 레이업의 반대 무릎은 밀기 중부터 올라간다. 숨긴 프로토타입의 더 큰 신발 좌표로 실제 발끝을 덮어쓰지 않는다.

팔은 직전 실제 손 위치/방향을 골반 상승과 함께 가져와 릴리즈 위치로 편다. 이미 공을 모았는데 다시 고정된 포켓으로 돌아가던 중간 목표와 중복100ms 진입 보간을 제거했다. 보조 손 분리와 손목 팔로스루는 유지하고, 내려오는 팔도 착지 때 골반 높이를 따른다. 드리블 공을 모으는180ms와 레이업의 양손 포켓→선택된 슈팅 손100ms는 직전 실제 공 위치에서 이어 공이 다른 손 쪽으로 튀지 않게 한다.

착지 전 미리 웅크렸다 펴지는 장식 대신 발이 바닥에 닿은 뒤 하강 속도를 감쇠된 압축으로 받아낸다. 압축은 약55ms 부근에서 가장 깊고 이후 회복한다. 실제 발끝은 착지 지점에 고정하고 상체도 부하에 맞춰 조금 숙였다가 돌아온다. 기존에는 공을 놓으면 이동 입력이 느린 속도로 캐릭터를 끌어 착지 발을 프레임당2.5cm씩 미끄러뜨렸다. 슛/레이업/덩크의 위치는 착지 회복이 끝날 때까지 동작 궤적이 맡고, 일반 이동·크로스오버 반응은 바꾸지 않는다.

새 모션캡처 클립이나 새 외형을 넣은 변경은 아니다. 같은45본 리그의 실제 접촉 계층과 전신 연결을 다듬는 범위이며 시각적 자연스러움은 별도로 계속 평가한다.
