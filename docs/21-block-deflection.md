# v0.9.5~0.9.6 — 블록 타격 후 공 이탈과 루즈볼 경합

2026-10-27. 사용자 확정: 블록 성공 직후 슈터가 바로 공을 다시 잡는 흐름을 바꾸고, 손바닥으로 맞힌 공이 확실히 튀어나오게 한다. 앞서 요청한 일반 루즈볼의 즉시 접촉 획득에 블록 타격 직후 예외를 둔다. Godot4.7.2 Standard/GDScript/Compatibility와 기존 리그를 유지한다.

## 설계와 구현

- 기존 속도는 수비가 슈터를 바라보는 전방을 향해 공을 내려쳐, 공이 다시 슈터 몸을 통과하고 다음 틱에 확보됐다. 타격 순간의 공격/수비 축에 수직인 양쪽 옆 공간과 약간 비튼 방향을 조사해, 몸통과 겹치지 않는 쪽을 선택한다. 3대3에서는 모든 보이는 선수의 이동·신장·공중 높이와 코트 경계도 참고한다.
- 공은 실제 접촉 위치에서 옆으로8m/s, 아래로7m/s로 출발한다. 공을 몸 밖의 새 좌표로 옮기지 않는다. 팔 역시 선택한 이탈 방향으로 내려치고 회수한다. 실제 손바닥 접촉과 블록 타이밍·거리·앞쪽 범위·몸통 차폐·제쳐진 AI의 회복 조건은 그대로 사용한다.
- 타격 후0.18초는 어느 팀도 자동으로 공을 소유할 수 없는 짧은 공 이탈 구간이다. 그동안 이동·중력·바닥 반발·경계 처리는 계속 진행한다. 이후에는 정상적인 실제 접촉으로 누구나 잡을 수 있다. 림에 맞은 공과 일반 바닥 루즈볼은 이 제한을 받지 않는다.
- 1대1과3대3이 같은 타격 시작 함수를 호출한다. 팀전의 마지막 접촉·블록 기여·리바운드 경합 통계는 유지한다. 기존 체크볼/새 모드 진입에서 블록 상태를 지우고 현재 소유자를 유효한 슈터 기본값으로 둔다.
- 공개 v0.9.5에서도 덩크 블록 후 즉시 재획득 없이 공이 빠졌으나 골대 뒤 경계로 빠르게 아웃되는 사례를 확인했다. v0.9.6에서는0.4초의 수평 진행 방향까지 참고해 열린 코트 안을 우선한다. 아웃 자체를 금지하지는 않는다. 블록 아웃의 마지막 접촉은 수비이므로 1대1에서도 슈터 쪽 체크볼이 되게 고쳤다. 기존 3대3의 마지막 접촉 기준은 유지한다.

## 검증

- 새 `block_deflection_test.gd`: 실제 손바닥 블록6회, 30/60/120fps의 일반/팀전에서0.16초 동안 공이 소유되지 않고 접촉 지점에서 최소1.869m 이탈했다. 순간 이동은 없으며, 몸을 강제로 접촉시켜도 타격 초반에는 잡히지 않고0.19초 이후에는 양 팀 및 세 번째 선수도 잡을 수 있다. 여섯 선수가 모인 상황에서 혼잡한 쪽 대신 열린 쪽을 선택한다.
- `block_swat_test.gd`: 실제 접촉6회에서 초기 비행과 손에서의 분리를 다시 필수로 검사한다. 기존의 즉시 회수 허용 분기는 사용자 최신 요구에 맞춰 제거했다. 빈 공간의 동일 속도 비행도 검사했다.
- 경계 가까이에서도 열린 코트 방향을 선택하고, 1대1/팀전의 블록 아웃은 슈터 쪽·일반 미스 슛 아웃은 반대쪽 체크볼이 되는4조건을 추가 검사했다.
- 정상 속도 1대1 슛·직선/옆 달리기 레이업231조건, 실제 접촉216회와 상승 팔 접촉45회, 실패0. 기존 블록42조건·몸통/팔 스윙·접촉/착지·추격192조건·팀전 접촉12블록/12캐치·일반 루즈볼75조건·일시정지·팀전27조건·성장 팀전, 웹 수명 주기·번역702개×3언어·의상 패키징 통과.
- 초기 다중 모드 검사에서 팀전의 슈터3번이 연습의 두 선수 배열에 남아 참조 오류가 발생했다. 테스트 오류를 무시하지 않고 체크볼 초기화를 고쳤으며, 같은 연속 모드 전환 검사를 오류 없이 다시 통과했다. 타격 방향 변경 후 드문 팔 회수 검사 실패는 팔의 아래치기 깊이를 유지하도록 고쳤다.
- 일반 속도 로컬 브라우저 1대1에서 D키로 실제 AI 레이업을 블록했다. 공이 두 선수에게서 떨어지는 동안 소유자-1/loose가 유지됨을 화면과 읽기 전용 진단으로 확인했다. `artifacts/v095-local-duel-deflection.png`, `artifacts/v095-local-duel-trace.json`. 실제 휴대폰은 검사하지 않았다.

최종 공개 배포와 브라우저 확인 결과는 완료 후 기록한다.
