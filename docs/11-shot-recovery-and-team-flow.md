# 슛 회복·3대3 경기 흐름 조정

2026-10-26 로컬 미리보기. Godot4.7.2 Standard/GDScript/Compatibility 유지. 공개v0.8.2 재배포는 이번 작업에 포함하지 않는다.

## 동작과 조작

- 접근 방향의 발 지지를 보존하고 이륙 후 골대 방향으로 몸을 돌린다. 실제 릴리즈 때 얼굴·몸통·팔을 같은 조준 좌표로 정렬한다. 손목 꺾기→잠시 유지→팔 내리기→착지→지지 발 밀기→다시 달리기로 연결한다. 회복 지지는 실제 보이는 신발 좌표에서 시작한다. 공을 놓은 뒤 보유 자세가 남던 상태도 해제한다. 슛 입력·릴리즈·득점 시간은 유지한다.
- E/전용 버튼은 세 수비 선수를 순환한다. 기존 가까운 선수 선택은 두 명 사이에서 반복될 수 있었다. 공중 공/리바운드 경합 중에도 선택 가능하다. 현재 조작 직군·1/3~3/3과 밝은 발밑 링을 표시한다. 짧은 웹 입력은 일련번호로 보존하고 포커스 이탈/일시정지 때 무효화한다.
- 공 없는 가드는 윙·지원 위치, 포워드는 컷인·반대 코너, 센터는 짧은 스크린·롤·재배치를 반복한다. 실제 목표 도달과 짧은 대기로 다음 경로로 진행한다. 핸들러가 골밑에 진입하면 동료 목표를 바깥으로 비운다. 수비도 실제 상대 이동을 따라간다.
- W 추가 접촉은 **정면 최대0.10m**. 방향에 따라 서서히 감소하며 약49도 이상 측면, 뒤쪽, 헛디딤 회복, 공중, 박스아웃, 비보유자에 대해서는0이다. 수비 힘/자동 스틸/블록 범위는 증가시키지 않는다. 돌파 후 뒤쪽 수비가 다시 붙는 효과를 추가하지 않는다.

## 성능과 한계

- 코트·라인·공을 재질/그림자별로 묶고 비균일 배율 법선은 역전치로 변환한다. 문자·움직이는 리그는 보존한다. 반코트 그림자는 단일 직교 맵으로 변경했다.
- 3대3은 MSAA를 끄고3D 렌더 버퍼를 최대921,600픽셀(16:9에서1280×720)로 제한한다. 다른 모드는2배 MSAA/2,073,600픽셀 예산. 글자·버튼은CSS 해상도를 유지한다. 팀전3D의 계단 현상/선명도와 성능을 교환한다.
- 같은6인 장면 렌더 호출 약1,569→181회. 최종IAB/WebKit WebGL의1920×1080 전체화면/1280×720 렌더에서 **활성 경기360프레임 평균54.38ms, p95 83.3ms**. `artifacts/team-fullscreen-verified.json`. 끊김 완전 해결/60fps로 표현하지 않는다. 어댑터명만으로 실제GPU나GPU시간을 추정하지 않는다.
- 초기 측정은 일시정지가 섞일 가능성이 있어 최종FPS 비교에 사용하지 않는다. 개발 프레임 도구는 숨김/일시정지/종료 구간을 제외하도록 보완했고 정상 웹 빌드에서 임시probe 스크립트/파일을 제거했다. 후속 성능 조정에는 실제 사용자 기기의CPU/GPU 프로파일이 필요하다. Android/AAB·실기기 성능 검증은 별도다.
