# v0.9.1 — 블록 점프 입력과 정면 접근

2026-10-27. 사용자는 블록슛이 여전히 잘 되지 않는다고 보고했다. Godot4.7.2 Standard/GDScript/Compatibility와 기존45본 리그를 유지한다.

## 원인과 변경

- 웹의 슛/점프 버튼은 누른 상태만 Godot에 전달했다. 키나 터치가 두 물리 틱 사이에 눌렸다 놓이면 값이 계속 false로 보여 수비 점프가 발생하지 않았다. 특히 짧은 터치가 프레임이 늦을 때 빠질 수 있다.
- HTML의 합쳐진 키·터치 상태가 false→true로 바뀔 때 순번을 기록하고 Godot이 한 번 읽는다. 수비 jump의 누름에만 적용한다. 공격 중 슛 홀드/릴리즈와 짧은 페이크 규칙은 변경하지 않는다. 키 반복·동시 키/터치는 중복 발생시키지 않는다. `pointercancel`·`lostpointercapture`와 창 전환/일시정지는 해당 입력을 취소한다. 재개 시 중립 입력을 확인하기 전의 점프도 버린다.
- 블록 점프의 목표 방향 이동 상한을0.34→0.42m로 올렸다. 발의 준비·앞꿈치 밀기·착지, 실제 스킨 손바닥과 공의 연속 접촉 및 몸통 상대 하강 속도는 기존 방식이다. 공이1.15m보다 멀거나 점프 방향 뒤에 있거나 슈터 몸을 관통하는 판정은 계속 거절한다. 드리블에 제쳐진 AI 수비의 회복 제한은 유지한다.

## 재현과 검사

- 기존60fps 정면 준비 슛을 3직군·0.65~1.2m·입력 타이밍15단계로 조사했다. 예를 들어1.2m 간격의 가드는 연습/팀전 각각3개 타이밍에서 접촉했다. 접근 개선 후 동일 표본에서 각각4개였고, 센터는 연습7→8개·팀전8→10개였다. 합법적인 추가 접촉이 가능한 작은 범위 조정이며 모든 입력이 성공한다는 뜻은 아니다.
- 새 `block_quick_input_test.gd`: 웹 입력을 한 물리 틱 사이에 눌렀다 놓았을 때 연습과3대3에서 도약→실제 손과 공의 접촉→아래로 튕김을 확인한다. 길게 누르기, 취소, 창 전환/재개 전 중립을 확인한다. `web_lifecycle_test.mjs`에서 짧은 포인터/키 입력과 반복·취소 순번을 검증한다.
- 기존 블록 실전42조건(26접촉), 실제 손바닥 아래치기/몸통 회전·접촉 후 팔 회수와 착지, 3대3 전 선수 접촉,30/60/120fps에서 제쳐진 수비 추격/거리/몸통 차폐192조건, 다리 안정10,372샘플, 중단·재개를 확인했다. 블록 경로는 실제 공에 손이 닿아야 하며 원거리 성공을 허용하지 않는다.
- 기존 `defensive_play_test.gd`는9개가 실패했으며 변경 전 소스에서도 동일하게 실패했다. 화면 스킨 이전의 숨겨진 손 노드와 초기화되지 않은 수비 방향을 참조하던 검사였다. 실제 스킨 손바닥과 점프 방향을 명시하도록 fixture를 고친 뒤 실제 공중 캐치6회·블록6회·연속 접촉·착지 검사 실패0으로 통과했다.
- 독립 브라우저의 실제 블록 연습과390×844 모바일 크기에서 짧은 버튼 터치로 도약하고 블록 음성/공 소유권 전환을 확인했다(`artifacts/v091-mobile-block.png`). 수치 검사와 브라우저 크기 검사는 실제 휴대폰 실기기를 대체하지 않는다.
- 헤드리스 Godot는 `user://logs` 쓰기 및 시스템 인증서 저장소 경고를 출력했으나 각 테스트 프로세스는0 종료, 실패0이다. 처음 만든 입력 테스트는 `web_input`의 기존 JavaScriptObject 형식 때문에 Dictionary 대입에 실패했으며, 실제 웹 객체와 같은 속성을 가진 fixture를 지원하도록 Variant로 바꾸고 다시 통과했다.
