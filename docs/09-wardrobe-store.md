# 의상 상점과 수집 — 2026-10-26

## 구현 범위

Godot 4.7.2 Standard/Compatibility와 기존 45본 리그를 유지한다. 로컬 웹 상점에서 코트 코인으로 의상을 구매하고 상의·하의·농구화를 별도로 장착한다. 구매 전 입어보기와 회전, 컬렉션 한 벌 입어보기, 분류·컬렉션·보유/미보유 필터, 수집 현황을 제공한다. 경기 중 열면 경기 시간과 상태를 정지하고, 닫아도 자동으로 경기를 재개하지 않는다. 구입하지 않은 미리보기는 경기 외관과 저장 기록에 남지 않는다.

94종: 상의32·하의31·농구화31. 기본3종과 구매91종이며, 기존13종에 9개 테마×3배색×3부위=81종을 추가했다. 현재 의상은 같은 농구복·하이탑 메시에서 배색과9개 무늬(단색 포함)를 조합하는 방식이다. 서로 다른 실루엣의 의상94개를 새로 모델링했다는 의미는 아니다. 피부·얼굴·머리카락·체격·관절과 모션은 유지한다. 후속 모자·헤어·액세서리·다른 옷 형태는 별도 에셋 범위다.

## 경제와 저장

- 최초 선수/기존 선수 이관 시300 코인. 의상 가격90~2250 코인. 현금 결제·유료 충전·현금 전환·랜덤 뽑기는 제공하지 않는다.
- 육성1대1 첫 승리 `100+단계×20`, 재도전 승리 `40+단계×5`, 패배20 코인. 연습/일반1대1/AI3대3 보상 없음. 경험치와 함께 기존 `cr_finish_match` 트랜잭션에서 한 경기 한 번 지급한다.
- 기존 `cr_players.data.version=1`을 유지하며 `wardrobe:{version:1,coins,owned,equipped}`를 추가한다. 없는 기록은 기존 육성 자료를 보존하면서 기본 의상과 코인을 계산하고 첫 쓰기에 저장한다. 새로운 하위 버전은 덮어쓰지 않고 새로고침 오류로 안내한다.
- `buy`/`equip` API는 인증된 사용자와 서버의 카탈로그만 사용한다. 클라이언트가 보낸 가격·잔액·소유자·클리어 단계는 사용하지 않는다. `revision` 비교 갱신으로 동시 구매·훈련·보상의 덮어쓰기를 막는다. 이미 가진 의상을 다시 구매해도 추가 차감하지 않는다. 응답 유실 시 새로고침/동일 구매 재시도로 복구한다.
- 실제 AI 경기 입력 전체를 서버가 검증하는 경제는 아니다. 무료 솔로 PvE 수집 기능이며, 현금성 경제·온라인 경쟁 보상을 도입하려면 별도 경기 검증이 필요하다.

## 렌더링·모바일·확장

메시 UV.x의 정수 구간으로 저지·패널·바지·신발·끈·양말을 구분한다. 원래 정점·삼각형·가중치·UV2의 RUSH/등번호 인쇄를 유지하고, 인스턴스별 재질만 바꾼다. 기본 의상으로 복원하면 원래 재질로 돌아간다. 상대/AI 동료의 재질은 공유 변경하지 않는다. 표면7개와 기존 메시 수를 유지해 의상 수만큼 모델을 추가 다운로드하지 않는다.

세로 모바일은 상단 전신 미리보기와 하단 상품 패널, 가로/데스크톱은 좌우 분할이다. 터치 높이44px 이상, 한·영·일·중 이름/가격/해금 안내를 제공한다. Android는 같은 계정·아이템ID를 사용하도록 설계했지만 AAB/실기기 검증은 미완료다.

카탈로그 원본은 `assets/data/wardrobe.json`. `tools/expand_wardrobe.mjs`는 기존13개ID를 보존하며 현재9개 테마를 재생성하는 저작 도구다. 출시 후에는 기존ID/가격/소유권을 보존하며 카탈로그에 새 항목을 추가한다. `tools/sync_wardrobe.mjs`로 브라우저/Edge Function 카탈로그와 번역을 동기화한다. 의상 성장 효과를 추가하지 않고, 후속 콘텐츠는 신규 코트·도전 목표·별도 형태 에셋과 함께 확장한다.

## 반영 범위

웹은 로컬 `http://127.0.0.1:8791/` 미리보기 단계이며 이번 요청으로 GitHub Pages를 배포하지 않았다. 공유 Supabase의 `court-rush` Edge Function v4에 구매/장착과94종 서버 카탈로그를 반영했다. 기존 `cr_*` 테이블/버전1 데이터 형식을 확장 사용하며 DDL·다른 게임의 `ttk_*`·공유 Auth 설정을 변경하지 않았다.
