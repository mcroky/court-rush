# v0.9.4 — 1대1에서 슛을 보고 반응하는 블록

2026-10-27. 사용자가 일반 1대1에서 상대 슛을 보고 D/블록을 눌러도 성공하지 못한다고 재확인했다. Godot 4.7.2 Standard, GDScript, Compatibility와 기존 리그를 유지한다.

## 재현과 변경

- v0.9.3 정지 슛에서 상대 도약 후 0.1초에 누르면 가드·포워드·센터가 모두 실패했다. 손을 늦게 뻗었고, 구형 팔에서 제한한 끝점을 실제 스킨에 다시 맞추고 있었다. 블록 디딤 0.10→0.06초, 도약 0.62→0.82m, 뻗기 구간 0.08~0.18초로 조정하고 실제 스킨의 어깨·팔 길이로 접촉 곡선을 푼다.
- 최대 수평 접근 0.42m는 유지하며 이륙 직후에 접근한다. 높아진 착지는 무릎 하중 0.27m로 흡수한다. 리바운드 도약 곡선은 바꾸지 않는다.
- 아래를 향한 손바닥에 상승하는 공이 실제 닿아도 팔의 몸통 상대 수직 속도가 음수가 아니라는 이유로 취소했다. 이제 실제 손바닥/공의 연속 접촉과 손바닥 방향을 확인하고, 팔의 하강 또는 손바닥으로 들어오는 공의 상대 속도를 인정한다. 접촉 구간은 도약 동작의 0.13~0.46초이며 거리·앞쪽 범위·슈터 몸통 차폐와 제쳐진 AI의 회복 제한을 유지한다.
- 접촉 후 실제 팔을 몸 쪽으로 접으며 내린다. 끝까지 뻗은 손에서 다시 전방으로 길게 내리는 목표는 몸통 상승 중 닿을 수 없어 손이 떠 있었다. 공의 기존 아래/전방 타격 속도와 실제 소유권 규칙은 유지한다.
- 일반 브라우저 경기에서 AI의 달리는 골밑 마무리도 확인했다. 공 모으기 당시 위치 또는 옆 달리기 속도로 도약 방향을 고르면 실제 림 방향으로 들어오는 슈터를 놓쳤다. 동일한 실제 골밑 도약 목표를 예상해 발과 몸통 방향을 고른다. 손은 현재 화면의 공을 따라가며 예상 위치만으로 블록시키지 않는다.
- 기존 `?frame-probe=1`에서 읽기 전용 선수 위치·상대 동작·손바닥/공 거리와 접촉 여부를 DOM 속성에 제공한다. 실제 브라우저 재현용이며 경기 상태를 바꾸는 권한은 추가하지 않는다.

## 검사와 한계

- 새 `block_reaction_test.gd`: 정상 속도 1대1의 3직군·정면/45도 슛·다섯 반응 시점, 직선과 옆 달리기에서 골밑으로 들어오는 레이업을 30/60/120fps로 검사했다. 최종 231조건·실제 접촉 216회·상승 팔 접촉 45회, 실패0. 늦거나 먼 공은 실패하며 실제 접촉과 내려치기·팔 회수를 확인한다. 통제된 표본이며 경기의 모든 입력 성공률이 아니다.
- 동일한 정지 슛/늦은·먼 슛 141조건을 v0.9.3에 적용했을 때 접촉111회, 변경 후135회였다. 새 실제 레이업 경로 검사는 별도로 추가했다.
- 브라우저의 일반 속도 1대1에서 가드로 AI의 실제 레이업을 D키로 블록했다. 접촉 시 손바닥 하향0.90, 손/공 연속 거리0.148m와 상대의 실제 즉시 회수를 확인했다. `artifacts/v094-duel-trace.json`, `artifacts/v094-local-duel-block.png`. 초기 시도 중 슈터 뒤를 쫓아가다 놓친 사례도 있었으며 이를 성공으로 계산하지 않았다.
- 실제 스킨의 팔이 어깨 위로 뻗는지와 손바닥 방향을 검사한다. 연속 접촉 합성 fixture는 idle→block 손목 전환을 완료한 뒤 검사하도록 바꿨다. 틱 사이 빠른 입력, 착지, 3대3 접촉, 추격 회복, 루즈볼, 일시정지와 다리 안정 검사를 함께 수행한다.
- 기존 `block_swat_test.gd`는 v0.9.3에서도13회 실패했다. 몸에 닿으면 즉시 공을 잡으라는 사용자 요구와 반드시0.1초 동안 비행해야 한다는 단정이 충돌했다. 즉시 확보되면 블록/소유 표시를 확인하고, 미확보한 공에 비행 거리 검사를 적용한다. 즉시 확보 규칙 자체는 바꾸지 않는다.
- 개발 중 테스트 SceneTree를 fixture 함수만 쓰려고 생성해 지연 실행과 리소스 경고가 발생했다. 함수를 정적으로 호출하도록 고쳤다. 골밑 fixture도 최종 위치 배치 뒤 실제 손/발 포즈를 갱신하고 공을 모으도록 고쳤다. 해당 중간 결과는 최종 검증으로 사용하지 않는다.
- 수치 검사만으로 모션 자연스러움의 완성을 주장하지 않는다. 실제 휴대폰은 검사하지 않았다.
