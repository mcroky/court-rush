# 의상 형태와 점프슛 관절 연결 — 2026-10-26

사용자 요청: 색상만 다른 의상을 넘어 후드티·긴바지·모자·헤어를 추가하고, 가는 끈나시처럼 보이는 저지를 고친다. 이어서 점프슛에서 발 전체가 그대로 떠오르고 내려오는 동작을 개선한다. 기존45본 리그·게임 엔진4.7.2 Standard/Compatibility와 공 소유권·슛 타이밍을 유지한다.

## 실제 형태 에셋

- 상의4형: 저지·반팔·후드티·바시티 재킷. 하의3형: 반바지·조거·카고. 조합12개의 스킨 메시이며 기본 조합 외11개를 별도 리소스로 제작했다. 후드는 목 뒤에 내려놓은 형태이며, 소매·시보리·포켓·카고 주머니·긴 바짓단은 실제 정점으로 제작했다. 덮인 팔/다리 피부를 생략해 옷 관통을 줄인다.
- 저지의 문제 원인은 몸통 원통의 넓은 윗변을 목선처럼 쓰던 구조였다. 작은 목둘레로 모이는 어깨판과 좌우 암홀로 바꿨다. 기존 피부/얼굴과 농구복 등번호의UV2 인쇄는 유지한다.
- 모자4형: 캡·백워드 캡·비니·버킷햇. 기본 포함 헤어6형: 스윕·버즈·컬리·드레드·사이드파트·포니테일. 모자를 쓰면 원래 머리 표면을 숨기고 압축 헤어로 교체한다. 포니테일과 드레드의 외부 부분은 남는다. 머리카락은 현재 머리 본에 묶인 형태이며 별도의 물리 시뮬레이션은 없다.
- 머리 장식은 본래 Skeleton3D와 Skin을 공유하는 추가 MeshInstance다. 원래 리그·bind 순서·애니메이션 트랙과 게임 판정 크기를 변경하지 않는다. 의상은 접촉 판정이나 능력치 보너스를 주지 않는다.
- 기존94종ID/가격을 보존하고44항목 추가: 상의44·하의39·신발31·모자13·헤어11, 총138종. 모자 없음과 기본 헤어는 무료 기본 지급. 실제4×3개의 몸통 형태와 독립 머리 장식을 사용한다. 형태 필터와5개 부위 탭을 추가했다.
- 원본 저작 도구와 에셋 목록/크기·출처는 `assets/characters/wardrobe-asset-manifest.json`. 웹 팩46.2MiB, 전송용 gzip17.7MiB. 본체 표면7개를 유지하고 사용자 헤어/모자에서 추가 표면이 발생한다. 실제 Android 기기/메모리·발열 검증은 미완료다.

## 슛 연결 수정

종전 구현은 공중에서 발에 몸과 거의 같은 높이를 더하고, 도약 초반 이후 발목 회전을0으로 돌렸다. 무릎의 상대 위치도 거의 고정돼 발이 수평으로 통째로 상승하는 인상이 났다. 실제 움직이는 발 본에 다음을 연결했다.

1. 슛 준비에서 골반을 내려 하중을 받고,9/100초 밀기 구간에서 무릎을 펴며 뒤꿈치를 든다. 하중 깊이를 늘려30fps에서도 발목만 먼저 펴지고 무릎이 뒤늦게 움직이지 않게 했다.
2. 앞꿈치를 세계 좌표에 유지한 채 발목을 펴고 이륙한다. 양발 지지/착지에는8/18ms의 작은 시차를 둔다.
3. 공중에서 발목 각도를 유지하며 발을 조금 뒤로 접고 무릎을 구부린 뒤 착지에 맞춰 편다. 기존처럼 공중 대부분을 평평한 신발 자세로 보내지 않는다.
4. 앞꿈치 접촉 후65ms 동안 뒤꿈치를 내리고, 골반/무릎 압축 뒤 회복한다. 착지 전 무릎을 미리 꺾어 충격 흡수를 흉내 내는 대신 접촉 뒤 하중을 받는다.

기존 점프 곡선·도약/착지 기준 시간·슛 릴리즈와 경기 판정을 유지했다. 장신/단신 체형의 본 길이를 늘이지 않고 고정 길이 IK로 표현한다.

## 저장과 서버

기존 `wardrobe.version=1`을 유지하며 defaults/owned/equipped에 hat/hair를 추가한다. 기존3부위 기록은 코인과 보유ID를 보존하며 모자 없음/기본 헤어만 기본 지급한다. 현재 게임의 명시적 Supabase 선택과 기존 사용자 보존을 우선하며, 공통 문서의 Neon 전환 검토는 별도 환경/인증 이관 과제다. 이번 에셋 추가를 이유로 운영 인증과 DB를 이관하지 않는다.

공유 Supabase의 court-rush 함수v5에서 카탈로그만 확장했다. 서버 index.ts/rules.mjs의 내용이 직전v4와 동일함을 비교했고 DDL·ttk_*·공유 Auth 설정을 변경하지 않았다. 기존 공개v0.8.0 클라이언트의 구매/장착 API와 호환된다. 새 웹 게임 배포는 요청받지 않아 로컬 미리보기만 갱신한다.
