# 3대3 AI 팀전 — 로컬 구현과 후속 설계

2026-10-26 로컬 미리보기에 사람1명 + AI 동료2명 대 AI3명의 반코트 경기를 추가했다. Godot4.7.2 Standard/Compatibility와 기존45본 리그를 유지한다. 공개 v0.7.6과 구분하며, 현재 온라인 대전과 팀 육성 보상은 제공하지 않는다.

## 현재 플레이

- 첫 화면 또는 모드 선택의 `AI 3대3 팀전`으로 시작한다. 선택 포지션을 첫 선수에 적용하고 팀마다 가드178cm·포워드190cm·센터204cm를 구성한다. 테스트용 포지션/키/운동능력 프로필을 사용하며 서버에 저장된 육성 스탯을 이 모드로 불러오지는 않는다.
- 11점 선취 또는3분, 공격 제한18초. 동점이면 다음 득점으로 승부를 가린다. 득점 뒤 상대 팀 체크볼, 상대 팀에서 공을 얻으면 외곽 클리어. 같은 팀 패스는 공격 제한/클리어 조건을 유지한다. 슛 실패의 림 바운스와 블록 이후 루즈볼을 여섯 선수가 다툰다.
- 이동/슛/드리블/스틸/W 수비는 기존 조작을 공유한다. Q는 방향 입력과 열린 동료를 고려한 패스, E는 수비 선수 전환. 동료가 패스나 리바운드를 확보하면 해당 선수로 자동 전환한다. 모바일의 큰 문맥 버튼은 공격 때 패스, 수비 때 전환이며 일부 추가 드리블 기술은 키보드로 유지한다.
- 패스 준비→실제 양손에서 방출→가로채기 가능한 비행→받는 실제 양손 접촉→가슴으로 보호→드리블 복귀. 패스 중에는 소유자가 없으며 캐치 이전에 받는 사람에게 공을 붙이지 않는다. 자동 가로채기는 경로 도착 시간에 맞춰 손을 뻗고 실제 손과 공이 닿을 때만 성공한다.
- AI는 결정(0.18초 간격 목표/행동)과 매 프레임 조향/리그를 분리했다. 역할별 외곽·골밑 위치, 포워드 컷, 센터의 볼 핸들러 인근 위치 선정, 마크/근거리 헬프, 박스아웃/리바운드를 사용한다. 정교한 전술·스크린 콜·스크린 반칙은 후속 기능이다.

## 소유권과 모션 경계

`game.gd`의 연습/1대1 경로를 보존하고 `team_match.gd`가 팀전6인의 입력·AI·접촉 후보·공격권을 관리한다. 팀전에 들어가면 활성 배열이0~2 아군,3~5 상대가 된다. 나가면 원래 두 선수를 복구하고 추가 네 선수를 숨긴다. 선수 소유자(`ball_owner`), 팀 공격권(`possession`), 조작 선수(`selected`)를 구분한다. UI의 기존 소유자 표시는 조작 선수/상대/동료/공중으로 변환하고 실제 ID는 별도 상태로 제공한다.

일반 드리블에서는 같은 손목 목표와 팔 길이를 유지하는 팔꿈치 원 위에서 해를 골라 상완의 과한 후방 변위를 제한한다. 반대 손은 어깨 앞의 보호/균형 자세를 기준으로 발 박자에 맞춰 작게 움직인다. 이 제한은 다른 드리블 기술·슛·수비 점프에는 적용하지 않는다.

공 소지 시 양팔은 같은 실제 가슴 프레임에서 굽히고, 드리블 손의 누르기/받기와 반대 팔의 균형 움직임을 구분한다. 이동 중 공은 기울어진 상체보다 앞에 두고 정지 시 손목이 아래팔의 반대로 돌아가지 않도록 연결한다. 보유 높이는 각 체형 비율을 따른다.

슛 준비·도약·공의 실제 손 방출·궤적·림 반응과 기존 리그를 재사용하고, 득점·블록 접촉·소유권 확정은 팀 컨트롤러로 위임한다. 리바운드 후보는 모든 선수의 실제 양손을 검사한 뒤 거리/안정된ID 순으로 한 명만 확정한다. 블록은 상대 팀 후보만 검사하며 기존 몸통 차폐·팔의 상대 하강·손바닥 연속 접촉을 유지한다. 속임수 뒤 수비 회복도 기존 디딤/회전 리그를 사용한다.

패스와 받기는 기존 스킨 메시의 실제 손바닥에 새 양손 목표를 적용한다. 공의 비행과 손 접촉은 게임 쪽이 소유하고 화면 셸은 입력/문구를 담당한다. 터치 취소·포커스 이탈·일시정지는 Q/E와 터치 입력까지 함께 해제한다. 카메라는 전환된 조작 선수를 따라간다.

## 후속 범위

- 팀전 육성 수치/보상: 서버 팀 경기 티켓·진행 시간·기여·결과 검증 후 연동한다. 현재 Supabase Auth와 ttk_* 영역을 변경하지 않는다.
- 온라인6인: 서버 권위 공 소유권·입력 검증·동기화·재접속을 별도 구현한다.
- AI 전술/밸런스: 스크린 콜·헬프 복귀·패스 요청과 역할별 도전 과제, 난도 조정.
- 기기 검증:6명 스킨 메시·그림자의 휴대폰 GPU 성능, 실제 터치 동시 입력·수명 주기·Android 빌드. 브라우저 뷰포트 검사를 휴대폰 실기기 검증으로 기록하지 않는다.

검증 기록은 `docs/04-prototype-validation.md`에 유지한다. 로컬 기능 구현을 공개 출시/온라인/육성 보상 완료로 표시하지 않는다.
