# 모바일 온라인 표시 부담과 조이스틱

2026-10-28. 사용자: PC는 괜찮으나 갤럭시S24에서 약간 끊김, 조이스틱 조작과는 관계없음. 조이스틱을 조금 오른쪽으로 요청. 실제 S24 브라우저와 FPS는 미확인이다. 조이스틱 입력을 끊김 원인으로 단정하지 않는다.

Godot4.7.2 Standard/GDScript/Compatibility 유지. 설치 router 목록의 performance-optimization·game-ui-ux 지침 적용. 과거 GAMEDEV_SKILLS_GUIDE 경로는 없고 PROJECT_BASELINE13절로 통합되어 실제 기준을 확인했다. 작은 조이스틱 위치 수정이며 화면 흐름 재설계나 모션 생성 방식 교체는 하지 않는다.

## 측정과 변경

`artifacts/benchmark_online_view.gd`는 실제 온라인View·시각 예측·권한 리그를 인스턴스화하고60Hz 입력,20Hz 서버 상태, 총1320프레임 중 워밍업120을 뺀1200프레임의 view.tick 시간만 측정한다. 권한 판정 시간은 측정에서 제외한다. Windows headless 표본이며 S24 FPS나 GPU 시간은 아니다.

동일 조건의 평균 약10.8% 감소 표본. 원본 로그 mobile-view-before.log/mobile-view-after.log/mobile-view-after-full.log. 모든 휴대폰에서 같은 개선율이나 끊김 완전 해결을 뜻하지 않는다.

완전 로컬 예측 프레임은 어차피 덮어쓰던 서버 관절·루트·rig/model 변환 계산을 생략한다. 예측 관절을 직접 복사하고, 80ms 진입/이탈 중에는 기존 보간을 적용한다. 입력 메타데이터와 미확인 입력 JSON은 문자열이 바뀔 때만 해석한다. 필요하지 않은 구형 이동 재생도 실행하지 않는다. 서버 판정·업데이트 주기·화질·모델·조명·경기 규칙은 바꾸지 않는다.

터치 레이아웃의 조이스틱 transform에 가로 최대16px 이동을 추가하고 기존 세로 lift와 오른쪽 버튼 위치는 유지한다. 일반 휴대폰 폭에서는16px,340px 이하 좁은 화면은0px로 줄여 버튼과의 겹침을 방지한다. 실제 getBoundingClientRect를 사용하는 입력 중심도 함께 이동한다.

## 검증

기존 온라인 표시 검사 및 지연 예측 검사 통과. 추가 검사: 실제 브리지로 완전 예측 진입 후45개 bone origin/basis 오차1µm 미만, 실제 손바닥0.1mm 미만, 예측을 끈 뒤 서버 루트로 복귀. 측정1320프레임 중 완전 예측1316프레임, 직접 복사 관절 위치 오차0.

IAB 브라우저320×760·390×844·844×390 검증.390px 화면의 조이스틱 transform x16px, 실제 왼쪽38px/오른쪽126px, 동작 버튼 시작137px로11px 간격.320px에서는 x0px로 줄여 오른쪽76px/동작 버튼 시작80px의4px 간격을 보존했다. 실제 이동한 중심에서 포인터 드래그로 선수 이동 및 손을 놓으면 스틱 중앙 복귀를 확인했다. 가로 화면도 조작 영역 겹침 없음. 이는 브라우저 크기 검사이며 S24 실기기 FPS는 측정하지 못했다.
