# 온라인 1대1 서버 지연 측정

2026-10-28. 사용자 제보: 서로 다른 기기의 두 계정이 연결됐지만 양쪽 모두 끊긴다. 방 목록은 실제 QA 두 계정에서 생성 push·목록 ID 입장을 확인했고 사용자도 연결을 확인했으므로 경기 지연을 우선 조사했다.

## 변경 전

실제 Render 로그의 해당 경기 p95 틱 지연46.263~65.350ms, 표본 p99 최대67.480ms. 60Hz 틱 간격16.667ms를 초과한다. Render Metrics 화면에서 현재 Free는0.15 CPU/512MB로 표시되며 Free의 CPU 사용률 그래프는 제공되지 않았다. 할당량과 실제 CPU 사용률을 혼동하지 않는다.

비어 있는 코트에서 지정 QA 두 계정의 비공개 경기20초를 측정했다. 다른 이용자의 방·자동 매칭에 참가하지 않았다. 상태399개 간격 평균49.953ms / p95 94.835ms / p99 99.716ms / 최대111.507ms. 100ms 초과2개. RTT20표본 평균105.15ms / p50 97ms / p95 153ms. 서버 상태 tick 간격은 모두50ms로, 시뮬레이션 상태 자체는20Hz였지만 전달 간격이 고르지 않았다. 원본 `artifacts/online-latency-before.json`.

실측 패킷 간격을 재생한 보간 시계 비교에서 현재100ms 버퍼의 정지 프레임은0이었다. 단순히 버퍼만 늘리는 안은 평균 표시 지연을95→145ms로 늘렸으므로 적용하지 않았다. 이 결과를 사용자 기기에서 프레임 정지가 전혀 없었다는 의미로 해석하지 않는다.

## 서버 작업량 비교와 변경

동일한 실제 Godot 권한 워커에서 입력·판정은60Hz, 상태는20Hz로 유지하고 엔진 루프만 비교했다. Windows 실제 엔진 프로세스의 CPU 시간을 측정했으며 콘솔 런처 CPU0이라는 무효 측정은 제외했다.

| 엔진 루프 | CPU 사용 시간 / 벽시계 | CPU 한 코어 대비 | 약10.4초의 tick / snapshot |
|---|---|---:|---:|
|60Hz|1,875ms /10,377ms|18.07%|621 /207|
|30Hz|1,484ms /10,369ms|14.31%|624 /208|
|20Hz|1,469ms /10,392ms|14.13%|621 /207|

30Hz는60Hz 대비 약20.8% 감소. 20Hz의 추가 감소는 작고 입력 수집 간격이 더 길어져30Hz를 선택했다. 로컬 Windows 수치이며 Render CPU 사용률이나 모든 기기의 개선율이 아니다. `artifacts/worker-poll-benchmark.json`, `worker-poll-benchmark20.json`.

`Engine.max_fps=30`으로 제한하고 기존 누산기의1/60초 판정·60Hz 전체 손/관절 포즈·20Hz 상태 전송·양쪽 선수 외형·육성값·승패/Elo를 유지한다. 기존 v0.10.2 모션 캐시도 새 서버 패키지에 포함한다. 클라이언트 프레임 제한·화질·판정 빈도는 낮추지 않는다.

게이트웨이9개 통과. 실제 워커의 벽시계 대비55~65틱/s·18~22상태/s 및 시뮬레이션 시간=tick/60 검사를 추가했다.

## 실제 서버 재측정

Render에 `9012e78`을 배포하고 동일 두 QA 계정·동일 입력·20초 비공개 경기로 재측정했다. 각각 짧은 표본이며 호스팅 부하·네트워크 변동의 영향이 있다.

| 측정 | 변경 전 | 변경 후 |
|---|---:|---:|
|상태 간격 표본|399|399|
|상태 간격 평균|49.953ms|49.989ms|
|상태 간격 p95|94.835ms|70.246ms|
|상태 간격 p99|99.716ms|95.313ms|
|상태 간격 최대|111.507ms|102.982ms|
|100ms 초과|2|1|
|RTT 평균|105.15ms|99.85ms|
|RTT p95|153ms|119ms|

평균 상태 빈도20Hz 유지, p95 도착 간격 약26% 감소. 원본 `artifacts/online-latency-after.json`. 실제 두 사용자 기기의 FPS 개선율이나 모든 끊김 해결을 입증한 값은 아니다. Free의0.15 CPU, 지역 간 통신, 짧은 표본과 여전히 남는100ms 이상 지연을 고려해야 한다. 클라이언트 보간 시간을 늘리거나 영상 품질·손 접촉 판정을 낮추지 않았다. 유료 플랜 변경은 하지 않았다.
