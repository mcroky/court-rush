# 코트러시 · 모바일과 선수 육성 설계

**2026-10-24 v0.7.0 갱신:** 사용자 요청으로 모션 추가 보정은 보류하고 아이디 로그인·선수 생성·8단계 AI1대1·서버 성장 저장·스탯/기술 훈련을 구현한다. 아래 선행 설계의 미구현 표시는 당시 기록이며 최신 구현은 [계정·출시 구조](07-career-release.md),3대3은 [후속 설계](08-team-mode.md)를 따른다.

2026-10-24 사용자 확정: 이름은 **코트러시 · COURT RUSH**, 향후 모바일 출시, 스탯과 스킬 육성, 포지션은 **가드·포워드·센터**. 현재 구현 우선순위는 모션이다. 이 문서의 육성·포지션·스토어 출시는 계획이며 현재 게임에 구현된 기능으로 소개하지 않는다.

## 지금의 제작 순서

1. 달리기·정지·전환, 드리블, 슛·레이업·덩크, 스틸·블록·리바운드의 몸·손·발·공 연결을 먼저 확립한다.
2. 같은 동작을 자유 연습과 1대1, 키보드와 터치에서 검증한다. 느린 화면만으로 평가하지 않고 보통 속도에서도 본다.
3. 모션 품질 기준을 확보한 뒤 선수 프로필, 포지션 선택, 스탯·스킬 육성을 구현한다.
4. 기기 테스트를 거쳐 모바일 패키지와 저장을 검증하고, 이후 온라인 경기와 계정 동기화를 별도 개발한다. 웹 자유 연습과 1대1은 유지한다.

## 내 선수 한 명을 키우는 흐름

선수 생성 → 포지션 선택 → 연습/경기 → 경험치와 성장 포인트 → 스탯 배분·기술 훈련 → 기술 장착/외형 변경 → 다음 경기. 승패 외에도 슛·수비·리바운드 등 역할 수행을 평가하되 같은 행동 반복만으로 무제한 보상이 쌓이지 않도록 경기 종료 사건과 훈련 과제를 구분한다. 팀 운영형이나 수집형보다 내 선수의 성장과 조작에 우선 집중한다.

| 포지션 | 기본 강점 | 성장과 기술의 방향 | 유의할 균형 |
| --- | --- | --- | --- |
| 가드 | 이동·볼 핸들링·스틸 | 방향 전환, 드리블 연결, 외곽 슛, 상대 틈 만들기 | 골밑 경합과 리바운드에 상대적 약점 |
| 포워드 | 중거리·돌파·다양한 마무리 | 점퍼, 레이업·덩크, 균형 있는 공수 | 모든 능력에서 다른 포지션의 강점을 대체하지 않음 |
| 센터 | 블록·리바운드·골밑 경합 | 박스아웃, 캐치 안정성, 골밑 마무리 | 이동과 드리블에 상대적 약점 |

포지션별 기본치 + 투자한 성장치 + 장착 기술 효과를 분리해 계산한다. 같은 스탯을 반복 적용하거나 장착 해제 후 효과가 남지 않도록 한다. 초기 수치·상한·성장 속도는 실제 1대1 플레이 결과로 정하며 위 표는 방향을 확정한 것이다. 역할 변경 시 포인트 재배분 정책은 프로필 구현 전에 정한다.

스탯 후보는 이동, 핸들링, 슈팅, 골밑 마무리, 수비, 리바운드다. 능력치는 허용 범위 안에서 가속·회복·성공 확률·경합 효율에 반영하되 실제 손과 공이 닿는 조건이나 슛 거리 규칙을 우회하지 않는다. 스탯만으로 수비자를 통과하거나 손이 닿지 않은 공을 가져올 수 없다.

스킬은 기본 동작과 습득·장착 가능한 변형으로 나눈다. 기본 조작을 익힌 뒤 크로스오버·턴·비하인드·헤지테이션·투스텝, 마무리 기술과 수비 기술을 훈련한다. 단계별 효과는 명시된 회복/연결/상황별 효율처럼 사용자가 이해할 수 있어야 한다. 성장치가 관절 길이·손과 공의 접촉 박자를 매 프레임 바꾸지 않도록 동작 이벤트와 능력치를 분리한다. 기술 레벨을 올려도 발의 교대와 지지 발·공 소유 규칙은 같다.

1대1은 입력 타이밍과 위치 선정이 계속 중요하도록 능력치 차이를 제한한다. 향후 경쟁전에는 유사 성장 단계 매칭이나 능력치 보정 규칙을 검토한다. 육성 도입만으로 온라인 서버/매칭이 완성되는 것은 아니다.

## 모바일을 고려하는 현재 구조

- 엔진은 Godot 4.7.2를 유지한다. 경기 상태·동작 단계·접촉 사건은 공통으로 사용하고, 브라우저 HTML UI/키보드·터치와 향후 네이티브 UI/입력은 어댑터로 구분한다. 모바일을 위해 경기 규칙을 다시 만드는 경로는 피한다.
- 손/발/공의 실제 좌표와 접촉 순간을 기준으로 동작을 검증한다. 표시 프레임률이 달라져도 공 소유권이나 기술 횟수가 달라지지 않아야 한다. 입력은 이동 벡터와 행동의 누름/유지/해제로 전달한다.
- 가로 화면의 양손 조작을 우선한다. 노치·하단 제스처 안전 영역, 약 48dp 이상의 행동 버튼, 스틱과 주요 행동의 동시 입력, 포인터 취소/손 떼기/앱 전환 시 잔류 입력 해제를 검사한다. 많은 육성 기술은 제한된 장착 슬롯과 문맥 버튼으로 배치해 화면을 가리지 않도록 한다. 버튼 크기 조정과 배치는 모바일 UI 단계에서 실제 기기로 결정한다.
- 현재 발 교대와 접촉 모션에 먼저 투자하되 모델 교체 때 사용할 준비·접촉·회수·착지 단계의 의미를 유지한다. 스킨 모델/애니메이션으로 옮길 경우에도 하나의 공 소유 상태와 손 부착 지점을 공유한다.
- 목표는 지원 중급 기기의 60fps이며 이는 아직 측정한 보장이 아니다. 30fps 환경의 입력/접촉 안정성, 발열·지속 플레이·메모리·로딩도 별도 측정한다. 품질 단계에서는 그림자·배경·이펙트를 조절하고 규칙과 접촉 판정은 유지한다.
- 화면 잠금·통화·백그라운드 전환·오디오 중단·방향 전환을 기기에서 검증한다. 진행 중 경기는 명시적인 재개 전까지 멈추며 입력을 비운다. 현재 웹의 일시정지 원칙을 네이티브 수명 주기에도 적용한다.

## 저장과 출시 단계

육성 저장은 버전, 선수 ID, 포지션, 경험치/레벨, 사용 가능 포인트, 투자 스탯, 스킬 단계/장착 슬롯을 가진다. 표시용 능력치 합계와 성장 원본을 구분하고 파일/브라우저 저장을 읽을 때 범위·형식·합계를 검증한다. 저장 실패를 알리고 이전 정상 자료·백업/내보내기·업그레이드 변환을 설계한다.

현재 시제품은 설정만 저장하며 육성 데이터는 아직 없다. 웹 로컬 저장과 Android/iOS 로컬 저장의 지속성은 각 플랫폼에서 검사해야 한다. 향후 계정 연동에서는 서버가 성장과 보상을 검증하며, 브라우저의 임의 수치를 경쟁전의 권위 데이터로 믿지 않는다. 웹→모바일 이전과 동기화 충돌은 계정 기능 개발 범위로 다룬다.

모바일 출시는 웹 화면 테스트와 구분한다. Android/iOS 내보내기·서명, 실제 기기의 조작/화면/성능/저장/앱 전환, 스토어 요구사항과 이름·상표 중복, 개인정보/저장 안내를 출시 시점에 확인한다. 스토어 등록·온라인 계정·결제는 현재 모션 작업의 구현 범위가 아니다.


## 2026-10-24 · 포지션 시험 밸런스 선행

사용자가 림 미스·박스아웃·리바운드의 역할 차이를 현재 경기에서 확인하도록 요청해 v0.6.21에서 G/F/C 기본 프로필 선택을 먼저 구현했다. 이동, 리바운드 도약/공중 이동, 박스아웃 버티기를 비교하는 시제품 범위이며 성장 포인트·기술 훈련·레벨·선수 저장은 아직 구현하지 않았다. 이전의 포지션 선택 전체 후순위 문구보다 이 변경을 우선한다. 같은 모델과 실제 손 접촉 판정을 쓰며, 경쟁전/모바일 실기기에서 확정한 밸런스로 취급하지 않는다.
